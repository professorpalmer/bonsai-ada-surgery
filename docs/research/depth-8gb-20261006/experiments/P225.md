## Question

P224 D2 (after a restart) answered Q2 wrong at ~200k, but the same Q2 was right at 4k. Is the restore exact, or does the
model give the wrong answer at this depth without any restore?

## Why

A restore that changes answers is a product fault and needs a new issue. A wrong answer at depth with no restore is a
limit of the model.

## Plan and gate

Script header (declared before the run): "The same conversation (P224 arm D: depth 200000, turns 1-4, --short 2,4) on ONE
server with no restart (arm M, the in-memory reference), the same zip, launcher, layer runner and env. Gate (declared
before the run): M answers byte-equal to P224 D on turns 1-4 -> the restore is exact and the Q2 / Q3 errors are the model;
any difference -> the restore changes answers (a new issue with both transcripts)."

## Deviations, incidents, void runs

- Found by this record writer: after turn 2, M saved 199,226 tokens and D saved 199,227 (layer logs). Turn 3 then read
  3,979 new tokens in M and 3,978 in D. Both reach the same 203,211 tokens after turn 3. So the two histories differ by one
  token position after turn 2, although the turn-2 answer bytes are equal. The cause is not in the receipts. A one-token
  shift of the same kind is in the #138 corrections post for P211 / P212 (138,526 against 138,525 tokens restored).
- The M turn 2 wall (8.14 s) is 2.09 s longer than D2 (6.05 s), which had a restart and a 2.87 s restore. The layer logs
  "after-answer test c8ff3e3be5ef pass (exact)" before M's turn 2 request line. The receipts do not show what the extra
  time is.
- The gate asked for byte equality, and the whitespace form of turn 4 was a known near tie (P213). The gate did not allow
  for it. The verdict below reads the content; the letter of the gate is FAIL.
- The copy of the queue script in `scripts/` differs from the rig file in one word of the first comment line; the code is
  the same.

## Verdict

FAIL by the letter (3/4 byte-equal). On content the restore is exact: with no restart the model gives the same wrong Q2
and Q3 answers at ~200k, and the same correct Q1 and Q4. So the Q2 / Q3 errors of P224 are the model at depth, not the
restore. No restore issue is needed.
