## Question

In a long agent-like session (the P164 soak), does the T5 window 32k give the same answers as the full read, and how
much faster is each turn?

## Why

The proposal's 4070 gates include "a long agent soak" (#138 21:54:09Z), and the release plan has R5: "30 turns from
~131k to ~245k, P164-style, layer on with the cache" (21:58:42Z). The 2060 has P164 as the dense reference for the same
driver and questions.

## Plan and gate

Script header (declared before the run): "bin-t5r3 with LLAMA_PREFILL_WINDOW=window=32768,sink=1024,tail=1024 via the
1017 launcher copy (BONSAI_BIN), slot save path, defaults otherwise; the serve-1017 layer (zip layer + #159) by
p164_layer.py on :8081 with the cache on. Driver p155_turn.py as P164: a ~131k document, then ~4k tokens of tool output
+ a question per turn, 30 turns (to ~250k), thinking off, temp 0, server + layer restart before every 3rd turn. Gates
(declared before the run): the P164 gates (30/30 answers, 0 one-token, 0 CUDA errors, restart turn wall <= 2x the
median at that depth, trace min free >= 60 MiB); reported against P164 (dense): per-turn wall (model: ~44 -> ~15 s at
250k), and answers equal to P164 turn by turn."

## Deviations, incidents, void runs

- Found by this record writer: the line was 86,528 in all P184 servers. P164 had 79,872 (turn 1 server) and 80,640
  (the restart servers). With ~6k more cells in VRAM, a part of the speed-up can come from the line and not from the
  window. Not measured.
- Found by this record writer: the P185 builds (`build_mmqv.sh`, -j 4) ran 17:57:38-18:11:45 (build_ahead.log), during
  turns 1-13 of P184. The CPU load can make turns slower; not measured.
- Found by this record writer: the restores took 2.37-6.22 s (P164 2.05-3.36 s); the cause is not known.
- P184 also differs from P164 in the bins (bin-t5r3 vs the zip bins) and the launcher (the 1017 test copy vs
  serve-1017's own). bin-t5r3 with the window unset gives the zip hash at 4k (P180).
- The plan's model figure "~15 s at 250k" did not hold: a normal turn at ~250k took 27.4 s (prompt 25.3 s).

## Verdict

PASS on the P164 gates as P164 read them. All 30 answers equal P164's, and the whole session takes 1,504.4 s instead of
2,272.6 s (1.51x); restart turns gain most (1.53-1.84x). The soak asks about the session's own text, which the window
keeps. It does not test a single question deep in a long document (the R2 sets, E89).
