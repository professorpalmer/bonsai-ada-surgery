## Question

Is the published bundle-20261017b zip the release that was tested, and does its own launcher with defaults read at the
P168 speed, print no spill line on a normal read, and print the line when a program fills the card?

## Why

bundle-20261017b ships the spill guard v6 (PR #164) and the layer read ahead (PR #159). The bins are the
bundle-20261017 bins. R4 is the 2060 check on the downloaded zip.

## Plan and gate

Script header (gates declared by the release session, #138 10:51Z): "zip 616,671,821 B, SHA-256 6285cd5d...e79ce; bin/
= bundle-20261017; changed: README, start-server.ps1 (v6 spill guard), layer. The ZIP'S OWN start-server.ps1 runs
unmodified, defaults ... Gates: 1) sha256 match; 2) zip launcher defaults: one cold 64k read within 2 % of P168
(309.3-309.6 tok/s) and 0 spill lines; 3) one ballast (free - 100 MiB) after the read: the spill line within 45 s; 4) 0
CUDA errors." The notebook (07:25 CDT) adds: "all bin/ files compared to bundle-20261017 (sha256 in Python; the runner
has no sha256sum)."

## Method

gh release download; Get-FileHash; a Python byte scan of the zip launcher (bytes < 32 other than tab / LF / CR) and a
Python sha256 compare of every `bin/` file with `release_1017/x/bin`. One server, 20 s wait after /health, one cold 64k
read (`p168_read.py`, salt r4_64), a 5 s nvidia-smi free-VRAM trace, then a (free - 100) MiB torch ballast and a
1 s poll for the `spill` line for 45 s.

## Deviations, incidents, void runs

- The layer was off in this test, because the layer runtime was not fetched in the test folder (#138 13:07:34Z).
- The sparse calib key did not match (the line moved to 87,808), so the bands were timed again. The #138 post calls this
  the expected behavior (the key holds a rounded line, P150).
- The #138 post says "The 231 MiB in the spill line is the 58 MiB ballast plus its torch CUDA context." The torch
  context size was not measured separately.

## Verdict

PASS. The bundle-20261017b zip matches its published hash; its bins equal bundle-20261017; its own launcher with
defaults read a cold 64k at 308.6 tok/s (-0.2 % vs P168) with 0 spill lines, printed the spill line 28 s after a 58 MiB
ballast, and had 0 CUDA errors.
