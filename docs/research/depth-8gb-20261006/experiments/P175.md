## Question

How much does an exact skip of fully masked K/V chunks cut the cold read with the T5 window, and are its answers the
same as the mask-only screen?

## Why

On 8 GB, deep prefill attention runs in K/V chunks (`GGML_CUDA_FA_CHUNK=32768` from the launcher: q3_0 -> f16 per
chunk, then FA, online-softmax merge). Notebook (11:19 CDT): "New: fa_chunk_any reads the packed mask once per op (one
small kernel + one sync) and the loop runs only the chunks that some row keeps; first / last flags follow the kept list.
A fully masked chunk adds nothing to the softmax, so this is exact: dense ops never skip (the last chunk holds the rows'
own cells); with the T5 window only the sink chunk and the window chunks run. GGML_CUDA_FA_CHUNK_SKIP=0 turns it off."

## Plan and gate

Script header (declared before the run): "S-0: env unset = product, in-block: det_answer 4k + 32k, zip then t5s: equal
sha256 (the skip never fires on a dense mask). S-1: n24 at 245k, window=16384,sink=1024,tail=1024, default chunks
(GGML_CUDA_FA_CHUNK=32768 from the launcher): the 24 answers equal P174b's (23/24; the skip is exact); report the cold
time vs P174b 1,452.2 s (mask only = dense speed). S-2: the same with GGML_CUDA_FA_CHUNK=8192 (finer chunks: fewer kept
cells): report the cold time and n24 (chunk merges change rounding, so answers may differ from S-1). S-3: a cold 128k
read (p168_read.py) with the window, the faster chunk size of S-1 / S-2: vs dense ~532 s (P168). 0 CUDA errors."

## Verdict

S-0 PASS. The fixed-grid chunk skip cuts the 245k cold read with the 16k window from 1,452.2 s to 991.0 s (1.47x) at 32k
chunks, with n24 22/24 (vault 15, a known borderline item, changed). At 128k the 32k chunk grain keeps most chunks:
484.1 s, 1.10x. 8k chunks crashed (P177).
