## Question

On the 2060, how much faster is a cold 128k / 245k read with T3 (FRAC 1/2, query tile 64) than dense on the same
bins, and does T3 run without CUDA errors?

## Why

P151: attention is ~65 % of a cold 245k read. T3 skips key pages per query tile past the VRAM line. The 4070 measured
1.159x at 245k (T3-S3) and asked for a 2060 probe.

## Plan and gate

Script header: "Cold reads, one fresh server per read (run_arm.sh, quick_tps at one depth): 128k dense, 128k T3
(GGML_CUDA_FA_PREFILL_SPARSE=0.5, GGML_CUDA_FA_PREFILL_SPARSE_QTILE=64), 245k dense, 245k T3, 128k T3 +
GGML_CUDA_FA_CHUNK_STAT=1 + GGML_CUDA_FA_PREFILL_SPARSE_STAT=1 (sm_75 time split; last CHUNK_STAT / T3 op lines).
Rule (declared by the kernel session): T3 >= 1.15x dense at 245k on the 2060 -> T3 goes to the full 2060 gates. Report
TTFT per read and the CUDA error count. No quality claim from this run."

## Method

run_arm.sh per arm (fresh server; quick_tps code prompt at one depth, then two short prompts); TTFT of the code prompt;
"CUDA error" lines counted in each server err log.

## Deviations, incidents, void runs

- The t3_128 / t3_245 .stat.txt files are empty (the STAT lines need the stat switches; only t3stat_128 has them), as
  the script intends.
- "min free at end" is run_arm.sh's end reading, not a trace minimum; t3stat_128 read 56 MiB (below the 60 MiB of the
  release checks; no trace in this run).

## Verdict

DONE: the speed rule is met on the 2060 (cold 245k 1,693.33 -> 1,384.78 s = 1.223x; 128k 1.095x; 0 CUDA errors). No
quality claim. The full T3 gates (kernel session, 00:31Z) then failed on the 4070 (G2: n24 dense 24/24, T3 22/24, losing
vaults 14 and 15), so T3 stays an opt-in experiment and does not become the 8 GB default; the 2060's G1 / G3 / G4 were
dropped as asked.
