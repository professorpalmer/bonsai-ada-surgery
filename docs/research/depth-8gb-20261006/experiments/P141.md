## Question

On the 2060's own wider item set at 245k (code n 20, needles n 24), does the shipped FRAC 1/16 rule equal dense, and
does FRAC 1/8 equal dense while it keeps >= 1.5x of dense decode?

## Why

The 4070's R10 at 245k: FRAC 1/16 lost a copy (_check_tzname, 0.128) and two needles (vault 13 at 0.521, vault 15 at
0.604) that dense got right. R10b (FRAC 1/8) was dense in substance on their set. PR #95 (FRAC 1/8 for
BONSAI_SPARSE=1) merges only if P141 passes.

## Plan and gate

Script header: "Gate (declared here, before the run; = R10 / PR #95 rule): per item vs dense for sparse16 and sparse8;
FRAC 1/8 qualifies if it equals dense on every item and keeps >= 1.5x of dense decode at 160k and 245k (dense: P135
10.6 / P139 6.2, same bins family)."

Amended before the run (PR #99, 05:27Z): merge if P141's FRAC 1/8 arm "(a) is not below FRAC 1/16 on any item of the
2060 set, (b) not below dense on any item in the droppable host tail, (c) >= 1.5x dense at 160k and 245k". Reason:
R10b's strict miss (_check_tzname, cells 30,772-30,823) is inside the VRAM line.

## Method

245k, a fresh server per test: code_needle --n 20 and needle_depth --n 24 for dense, sparse, sparse8. Then speed
160000 -> 245000 for sparse16 and sparse8, one server each, 10 s trace.
