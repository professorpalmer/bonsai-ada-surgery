## Question

P201 showed that the SM clock stays on the V-F curve. Does a core offset of +100 MHz with the 215 W limit make cold reads
faster, and does it keep the exact output?

## Why

Slot 3 was stable and exact for decode on 2026-10-06 (P4 / P9), but prefill was not tested. Script header: "Core
offsets can fail silently, so the identity gate matters most here."

## Plan and gate

Script header (declared before the run): the P201 arms (S1, W1, S2, W2: det 4k + cold 64k; then W3 and S3: a cold
240k-class read). "Gates: identity: the det 4k hash is equal in every arm (and = P201 d72631aab936fc4e); applied: 215 W
in W arms and 175 W in S arms, SM median in W at least +60 MHz over S (else the offset did not apply); speed: mean W 64k
beats S by > the S spread; heat: max GPU temp < 85 C in every arm; 0 CUDA errors. The card ends on slot 5 (stock)
whatever happens."

## Deviations, incidents, void runs

- None in the run. The P201 install had already put slot 3 in place (no install step here).

## Verdict

PASS on every gate. Slot 3 (215 W + core +100) reads +5.1-5.9 % faster and decodes +3-5 % faster on this card, with the
exact det 4k output and a max of 79 C. A 30-turn soak decides if it is a safe optional tune (P203).

## Corrections later

- P203: 30/30 answers equal to stock in the agent session; P207 / P208: core +150 is faster at 64k but slower past ~125k.

## What it changed

- P203 (the soak) was queued at once. Posted with P201 (13:43:39Z): "If it passes, it is an **optional** tuning line for
  2060 owners ... It is not a default, because cards differ."
