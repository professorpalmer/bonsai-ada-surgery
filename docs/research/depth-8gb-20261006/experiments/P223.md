## Question

past it) and its speed on the 2060?

## Why

shows the 8 GB line and speed. The bins are the bundle-20261019b bins, so only the launcher default changes.

## Deviations, incidents, void runs

- Try 1 is void because of a test-setup error, not a product fault. The script served the serve folder `serve-1019c`,
  which holds a different API key than the repo. `run_arm.sh` sends the repo's key file
  (`--key-file .../bonsai-ada-surgery/artifacts/api_key.txt`), so every request got 401. The try 2 script says so in its
  header. This record writer compared the key files without reading them out: the serve folder's key differs from the
  repo's, and the extract's key equals the repo's.
- Found by this record writer: the try 2 4k server got line 91,648 (7,786 MiB free, other programs 406 MiB), not 92,160.
  The 4k prompt and its answer fit far below either line.
- The zip SHA and the "bins = 19b" claim are not in `receipts/p223/`. This record writer checked them: `sha256sum` of
  `release_1019c/bonsai-bundle-win-x64.zip` is e84d8c6d21deaea1...26cbf9cb, the same as the GitHub asset digest (616,414,078
  B); all 16 `bin/` files of the 19c extract are byte-equal to the 19b extract; `start-server.ps1`, `layer/bonsai_layer.py`,
  `README.md` and docs files differ (the release R1 gate lists the same changes).
- The check started about 10 h after the release. Notebook 08:57 CDT: "I stalled ~10 h after the release (no watcher on
  the release)".
