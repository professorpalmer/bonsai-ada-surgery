## Question

Is GGML_CUDA_FA_PREFILL_NCOLS2=2 on sm_75 good enough in quality to be the Turing default: PPL / KL at 4k and 16k,
a cold 245k speed gain, and the 245k item sets item by item?

## Why

P154: NCOLS2=2 kept the 4k answer bytes on the 2060 and cut cold TTFT 1.067x (64k) / 1.110x (128k), but the 4070's
answers differed on 2 of 3 prompts. The kernel session (11:03Z) asked for quality gates instead of byte identity.

## Plan and gate

Script header (gates as declared by the kernel session, copied before try 1; order, stop at the first fail):

- "Q1 PPL + KL at 4k and 16k vs default (NCOLS2 unset): KL <= 0.001, same top-1 >= 99.5 %, PPL within +-0.2 %.
  llama-perplexity, wiki.test.raw, q3_0 K/V (the 8 GB default), -b 2048 -ub 512, the 8 GB preset's FA env
  (GGML_CUDA_FA_PREFILL_F16=32768, GGML_CUDA_FA_CHUNK=32768). 4k: 16 chunks; 16k: 4 chunks."
- "Q3 a cold 245k pair, fresh server each, zip launcher defaults: t2 vs default >= 1.10x on TTFT."
- "Q2 245k items: code_needle n 20, needle_depth n 24 and n 28, fresh server per test, t2 vs default on the same bins:
  item by item equal."

P156c header: "This run re-reads the try-2 Q1 logs with the regex fixed (-?) and then runs Q3 and Q2 as declared. No
gate is changed." P156d header: "Q2 of T2a-2 only ... Q2 as declared in P156".

## Method

Q1: one llama-perplexity run with the default saves all logits (--kl-divergence-base), a second run with NCOLS2=2
computes KL against it; the parser reads "Final estimate: PPL" of the default run, and "Mean PPL(Q)", "Mean KLD" and
"Same top p" of the t2 run. Q3: run_arm.sh at 245000 per arm (one fresh server each; quick_tps code prompt). Q2: a fresh
server per test and arm, code_needle n 20, needle_depth n 24 and n 28 at 245k; the summary compares items by key.

PASS. NCOLS2=2 on sm_75 keeps PPL (+0.02 % or less), KL (0) and top-1 (99.997 %) at 4k / 16k, makes a cold 245k read

## Toolbox (for the next model)

- Method: gate a kernel change that is not bit-exact on PPL / KL / top-1 at two context sizes plus item sets at depth,
  not on answer bytes (the 4070 differed on 2 of 3 prompts in P154 with the same kernel).
- Pitfall: a tool that runs inside another folder needs absolute paths for its outputs; check that an output file
  exists before the next step reads it.
- Pitfall: parse signed numbers with `-?` ("-0.000000" is a valid KL mean); a parser FAIL must be read against the log
  before it stops a run.
- Pitfall: key item compares by a unique item id, not by (file, function, position); one duplicate key hides an item.
