## Question

Is P207's slow long read a property of slot 4, or an outside event? Is the host side (CPU) the limit?

## Why

P207 had no stock long read in its block and no CPU log.

## Plan and gate

Script header: "repeat the long read, slot 4 then stock, in one block, with the CPU load logged (typeperf) to see
whether the host side (mask build, host-tail rows) stalls. Same gates." The arms that ran are W4 (slot 4) and S4
(stock), one P170 code item 1 read each.

## Verdict

Slot 4 falls behind past ~125k in both runs (P207, P208), so slot 4 is out. The CPU load stays low (mean 9 %), so CPU
contention is not the cause. The host-side path past the VRAM line varies from run to run (stock 1,417 vs 1,506 s), so a
deep cold read on this rig is noisy in that part. Slot 3 (P202 W3) led at every depth and stays the tested option.
