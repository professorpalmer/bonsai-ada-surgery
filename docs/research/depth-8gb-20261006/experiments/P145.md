## Question

Does the re-released zip (launcher fix) pick q3_0 by default on the 2060, with no control bytes in its launcher, and
keep the P130 q3_0 speed?

## Why

P142 found the shipped launcher never selected q3_0 (backspace bytes in a regex). PR #108 fixed it; bundle-20261015b
ships the fix. The test must run the zip's own launcher logic.

## Plan and gate

Script header: "Gates (declared here, before the run): sha256 match; the zip's start-server.ps1 has no control bytes
(0x00-0x08, 0x0B, 0x0C, 0x0E-0x1F); --version commit b86298dba9; FLASH_ATTN_EXT 0 FAIL; default launch (no BONSAI_CTK)
prints "window 262144 / q3_0" and a line of 78k-82k; sweep 4k / 64k / 128k within 3 % of P130 q3_0 (53.6 / 41.1 /
22.8); fresh 60k; 0 one-token; trace min free >= 60."

## Method

Download, sha256, Expand-Archive. A Python byte scan of the zip's start-server.ps1 (every byte < 32 other than 9, 10,
13). The test copy: the zip launcher with the `$Bin` line replaced by a BONSAI_BIN line. --version; FLASH_ATTN_EXT.
Sweep 4000 -> 64000 -> 128000 with a trace; one fresh 60k server.

## Results

- Zip sha match. "zip launcher control bytes: 0 []". Build 10798, commit b86298dba9. FLASH_ATTN_EXT 3115/3115.
- Default launch: "window 262144 / q3_0 (trained max 262144)", "cells 0..80128 in VRAM".
- Sweep: 53.2 / 40.8 / 22.7 at 4k / 64k / 128k vs P130 53.6 / 41.1 / 22.8 (notebook: "all within 1 %"); trace min
  free 83 MiB (75 samples).
- Fresh 60k: 40.0 tok/s; trace min free 111 MiB (27 samples).
- 0 one-token.
