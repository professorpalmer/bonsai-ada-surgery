## Question

What does the P164 session answer on the 2060 when the conversation never leaves memory? Does P211 (18f, cache on,
restarts) give those answers?

## Why

The 4070's gate for 18f is "answers equal to cache-off". P211 was compared with P205, which is an older cache path, not a
reference for exactness.

## Plan and gate

Script header (declared before the run): "the same 12 turns of the P164 session on the bundle-20261018f zip's own
launcher, the 18f layer via p211_layer.py WITHOUT --cache (no saves, no restores), one server for all 12 turns (no
restarts). ... Report: P211 (cache on, restarts) vs this, turn by turn (gate for 18f's claim: 12/12)."

## Results

| run | equal to cache-off | differ at |
| --- | --- | --- |
| **P211 (18f, cache on, restarts before 4 / 7 / 10)** | **12 / 12** | - |
| P205 after=1 (bundle-20261018 + save after, restarts) | 10 / 12 | 4, 10 ("4111\n9387" vs cache-off "4111 9387") |

- Walls: turn 1 555.84 s (the server read 130,487 tokens), turns 2-12 26.17-32.99 s. 0 CUDA errors.
- The P211 restart turns (4, 7, 10) took 30.20 / 34.14 / 35.92 s against 27.01 / 30.11 / 30.95 s here: a restart with
  a restore costs ~3-5 s on this card.

## Deviations, incidents, void runs

- None.

## Verdict

PASS for 18f's claim on the real 8 GB card: with the cache on and three restarts, the answers are byte-equal to a session
that never left memory. P205's two differences come from the old path.
