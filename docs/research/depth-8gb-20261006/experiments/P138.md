## Question

Does the published bundle-20261014 zip pass the 8 GB release gates on the 2060 with the default switches?

## Why

Every bundle gets a check on the downloaded asset on this card. bundle-20261014 adds patch 0055 (sparse with int8
bounds, opt-in BONSAI_SPARSE=1). With sparse off, nothing must change against bundle-20261013.

## Plan and gate

Script header: "Gates (declared here, before the run): sha256 match; ADD / RMS_NORM / FLASH_ATTN_EXT / GATED_DELTA_NET
pass; the zip bins report commit 4de6185494; default-off decode at 64k / 96k / 128k within 3 % of bundle-20261013 in
the same session (A/B alternated x2 below); sweep 4k-128k reported; fresh 60k x2; 0 one-token; trace min free >= 60
MiB. Note: the zip is a fat sm 75/86/89 build, so its ggml-cuda.dll is not byte-equal to the rig's 75-real bin-rc55
(hashes reported, not gated); P139 reruns the sparse checks on the zip bins."

## Method

As P126: gh release download, sha256, Expand-Archive; --version; op tests; bin hashes vs bin-rc55. A/B 1013, 1014, 1013,
1014 (one server each, 64000 -> 96000 -> 128000). Sweep 4000 -> 32000 -> 64000 -> 96000 -> 128000 with a 10 s trace;
two fresh 60k servers; lookup_ab.py at depth 0 and 64000 (22 items).
