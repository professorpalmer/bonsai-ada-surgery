## Question

Does a prefill window (the context tokens see only a sink + a local window in the 16 full-attention layers, while the
question rows and decode see all of the KV) keep the answers of a full read at 245k? This is a mask-only emulation, so
it screens quality before anyone builds a fast path.

## Why

The research entry (09:08 CDT, events E80): "Star Attention / SWAA: sink + local window for context tokens, FULL
attention for the query and decode (NIAH near dense on Llama; a naive window without dense query collapses); cost model:
W 16k + S 1k cuts 245k 1,489 -> ~650 s, W 32k -> ~760 s". "Why T3 lost needles: it made the question's own prompt rows
sparse too; Star / SWAA keep them dense."

## Plan and gate

P174 script header (gates declared before the run): "LLAMA_PREFILL_WINDOW="window=W,sink=S,tail=T": while a prompt is
read, ubatches that end before n_prompt - T mask cells S <= pos < p - W in the 16 full-attention layers; the tail (the
question) and decode stay dense. Mask only: the same speed as dense ... T5-0: env unset = product: det_answer sha256 at
4k and 32k equal to P169's zip hashes (d72631aab936fc4e / d77df25fc3f18819). C0 (engagement control): det_answer at 32k
with window=1024,sink=64,tail=0 must DIFFER from the dense hash; else stop. C1 (report only): 64k needle n8,
window=16384,sink=1024,tail=0: what the DeltaNet layers carry without dense question rows. T5-1: needle n24 at 245k,
window=16384,sink=1024,tail=1024: report vs the 2060 dense P148 23/24 (miss vault 14). T5-2: P170 code set and prose
set, the same window: report vs P170 dense 20/24 and 11/24. Screen pass (for a fast-path build): T5-1 >= 22/24 and
T5-2 within 1 item of dense on each set. 0 CUDA errors."

P174b changes T5-0 only: "T5-0 (P174b, in-block): det_answer at 4k and 32k, zip bins then bin-t5 with the env unset,
back to back: equal sha256 ... C0 ... must DIFFER from the in-block dense hash".

## Method

As P169 (det_answer, needle_depth) and P170 (p170_drive.py `--arm dense`: the full document, one request per item, the
server reuses the cached document). The server sets the dense tail from the prompt length. The window rule is in both KQ
mask builders (packed and float); the row-reuse index list also holds the window-edge band (notebook 09:08 CDT).

  same failure class as T4's "another needle's code".

## Toolbox (for the next model)

- Method: an engagement control (C0): a tiny window must change the answer bytes; otherwise the mask is not on and every
  later "same as dense" means nothing.
- Method: a probe of the recurrent layers (C1): window the question too (tail 0); the facts that survive show what the
  recurrent state carries across the gap (here only facts inside the window).
- Method: identity gates run in-block (product bins then test bins, back to back), never against a hash from hours
  before.
