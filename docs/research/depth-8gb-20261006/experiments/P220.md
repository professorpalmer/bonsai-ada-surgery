## Question

clean launcher with the new defaults, 0 CUDA errors, a long session with restarts, and no depth slower than the old
1 / 1 numbers by more than 3 %.

8 GB numbers (#138 22:16:16Z). Cary's wrap-up (22:46:32Z) closes #138 after this R6 and P219.

## Deviations, incidents, void runs

- Found by this record writer: gate 1 asks for "the replay line". The bundle-20261019b launcher prints no line when replay
  is on. It prints a note only when `BONSAI_RS_REPLAY=1` cannot take effect. The receipts show replay on indirectly: the
  launcher picks draft 2 only with replay, and P221's `BONSAI_RS_REPLAY=0` servers get line 82,432 and draft 1.
- Gate 2 compares with the card numbers (P150 / P163: other days, other bundles, 1 / 1 without replay). It is not an
  in-block A/B. The P221 script (written after this result) reads the speed gate from an in-block A/B.
- The soak comparison with P200 is not in-block either (bundle-20261018, 1 / 1, P200's line 86,016-86,528). It is
  reported, not gated. The byte-equal answers hold across these changes.
- `zip.txt` holds only the output of the `models` junction command. The zip size and SHA-256 are in the script header
  and the #138 posts. This record writer checked them again: `sha256sum` of `release_1019b/bonsai-bundle-win-x64.zip` is
  d5a53c2b2ad238e2...8328c561, and the GitHub asset digest and size (616,377,333 B) are the same.
