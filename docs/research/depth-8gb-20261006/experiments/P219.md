## Question

V-only 2-bit passes perplexity (P218). Does it keep long-context retrieval at 245k as well as q4_0, judged against a
rounding-only change?

## Why

PPL is an average over all tokens; a lookup deep in the window can fail on one value. Only a pass here makes a real mixed
K / V type worth an engine job.

## Plan and gate

Script header (declared before the run): "arms in one block: q4 = real q4_0; v2 = q4_0 with V rows faked to 2-bit
uniform (rot on); null = q4 with GGML_CUDA_FA_CHUNK=16384 (a rounding-only change). Per arm: needle n24 at 245k, then the
P170 code set. Gate: v2's confident-wrong answers where q4 is right <= null's count and <= 1 (n24 + code together); ok
counts reported."

Confident wrong (inline rule): not ok, holds a number of 2 or more digits, and has none of the "not in the text" words.

## Deviations, incidents, void runs

- Found by this record writer: the line was not pinned and differs by arm and server: n24 61,184 / 63,232 / 62,976
  (q4 / v2 / null), code 63,232 / 62,976 / 62,976. So the null arm is not a rounding-only change on n24 (+1,792 cells
  against q4). On the code set, v2 and null share the line (62,976), and v2 still has 1 confident wrong answer (15)
  where null has 0; on n24, v2 (63,232) has 1 where null (62,976) has 0.
- Found by this record writer: the #138 post and the notebook name the bins "kv-fake2v"; the folder is `bin-fake2v`, and
  the commit 37a51194f is on branch `kv-fake2`.
- The wrong-answer rule differs from P217's (P219 needs 2 or more digits); with P217's rule the counts are the same here
  (checked by this record writer).

## Verdict

FAIL. V-only 2-bit makes 2 confident wrong answers where q4_0 is right (a needle at 56 % depth and a code constant),
against 0 for the rounding null, and it moves 4 items against 1. With P216 (a full 2-bit KV fails PPL), KV below 3 bits
is closed on this model. q3_0 stays the 8 GB KV type.
