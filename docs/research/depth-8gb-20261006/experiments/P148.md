## Question

At 245k, where the automatic rule picks sparse, are the answers the same as dense item by item?

## Why

The 4070 (#105 23:38Z): the only end-to-end quality test of the shipped D26h setup with auto choosing sparse. P146
tested speed and determinism, not quality.

## Plan and gate

Script header: "Gate (declared here, before the run): auto = dense item by item on all three sets (needles strict;
copies as printed, lenient if strict differs only by whitespace); misses listed per item with position_frac. The auto
arm's engine log must show which choice the 245k bands got: if auto picked dense there, the result tests nothing new
and a forced arm (BONSAI_SPARSE=1, same 1/4 budget) runs on the same three sets, and the post says so."

## Method

245k, a fresh server per test: code_needle --n 20, needle_depth --n 24, needle_depth --n 28 (other positions), dense
then auto. The forced arm runs only if no "keeps N of M pages" line appears in the auto engine logs.

## Results

| set | auto | dense | misses (both arms) |
| --- | --- | --- | --- |
| code n 20 | 20/20 | 20/20 | - |
| needles n 24 | 23/24 | 23/24 | vault 14, position 0.562 (want 8104, answer 1968) |
| needles n 28 | 27/28 | 27/28 | vault 15, position 0.518 (want 7851, answer 2408) |

Auto ran sparse: the auto engine logs have "keeps N of M pages" lines (668 of 2675 pages in 15 lines; also 669 of
2679, 678 of 2715, 680 of 2723). The calib file was used (4 bands; unchanged before / after). No forced arm was
needed.

| gate | value | result |
| --- | --- | --- |
| auto = dense item by item on three sets | same items right, same misses | PASS |
| auto ran sparse at 245k | keeps 668-680 of 2675-2723 pages | yes (no forced arm) |

Rig note (notebook): "2060 dense n28 27/28 vs 4070 dense 25/28 (15, 19, 24)."
