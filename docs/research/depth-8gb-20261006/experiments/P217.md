## Question

Does draft 2 / tail 2 change the answers of a 240k lookup task more than a rounding-only change does?

## Why

P215: 2 / 2 decodes +21.8 % at 128k, but its greedy text differs from 1 / 1 (drafting rounding). Before it becomes the
8 GB default, the change must be no worse than rounding on a task with known answers.

## Plan and gate

Script header (declared before the run): "the P170 code set (24 inserted constants in ~240k tokens of code; 12 named + 12
described) ..., BONSAI_RS_REPLAY=1, driver arm "dense" (the full read), in one block: d11 = BONSAI_SPEC 1 / SPEC_DEEP 1
(the reference); null = d11 with GGML_CUDA_FA_CHUNK=16384 (a rounding-only change, as the 4070's null test); d22 =
BONSAI_SPEC 2 / SPEC_DEEP 2. Gate: "confident wrong where d11 is right" for d22 <= that count for null (and <= 1); report
all changed items, ok counts and cold times."

A confident wrong answer (inline rule): not ok, holds a number, and has none of "not ", "no ", "doesn't", "does not",
"cannot", "unable", "none".

PASS by the declared gate: draft 2 / 2 gives 0 confident wrong answers and 0 changed items against 1 / 1, the same as a
rounding-only change. With P213-P215 the 2060 data supports replay on + draft 2 / tail 2 as the 8 GB defaults.
