## Question

On the bundle as served, how fast does the first token come after a restart for a ~200k document that was read ahead,
and for follow-up questions?

## Why

P160 part C made the demo path work with the pool off on rig bins (restore 3.05 s + 2.9 s). The demo clip must show
the shipped files, with the first-token time a viewer sees.

## Plan and gate

Script header (gates declared before the run):

- "1. read ahead [user: a ~200k document] ("prefill_only": true) -> the one-time cold read; 2. restart (fresh server +
  layer); ask Q1 as a new message -> the restore + a short question; 3. same server: Q2 (Q1 + answer + Q2), then Q3 ->
  follow-ups in memory; 4. restart again; ask Q3's history once more -> a second restore, deeper"
- "Gates (declared before the run): read-ahead status "saved"; step 2 first token <= 10 s, wall <= 30 s; steps 3 first
  token <= 10 s each; step 4 first token <= 10 s; answers non-empty; 0 CUDA errors. Reported: all times, answers, the
  layer lines."

## Method

p165_drive.py: the t1b_slot document at depth 200,000 through the layer, streamed, `max_tokens` 200, temperature 0,
thinking off. The first-token time is measured at the client (the first content delta). Q1 "List the access codes of
vaults 1 to 8 ...", Q2 "Which vault has the largest code? ...", Q3 "What is the code of vault 3? Give the number only."
Each ask sends the whole history (document, the earlier questions and answers, the new question).

## Deviations, incidents, void runs

- The Q2 answer is wrong. The #138 post says it is "the same answer the cold read gives with thinking off". The cold
  reference is P153 / P160 (the short question "vault 4: 9320" on 200k reads); P165 has no cold control of its own.
- After the second restart the layer restored the read-ahead state (199,072 tokens), not a state with Q1-Q2. The
  request then read 186 tokens (the 3 questions and 2 answers). The layer saves again only after 8,192 new tokens.
- The cold read (1,068.6 s for 199,079 tokens) is faster than P160's 1,210.2 s for 199,107 tokens. The #138 post names
  the cause: the Turing prefill tiles of bundle-20261016b and later (P160 ran on bin-slotdraft, without the tiles).

## Verdict

PASS. On the shipped bundle, a ~199k document read ahead once (1,068.6 s) answers a new question 5.3 s after a full
restart (first token; restore 2.91 s), follow-ups in 2.5-2.6 s, and the same history 7.3 s after a second restart. 0
CUDA errors. The clip shows the speed; one answer (the largest code, thinking off) is wrong, as in a cold read.
