## Question

Does the published bundle-20261016b zip, with its own launcher, run the 8 GB defaults on the 2060 with the Turing
prefill tiles on and the cold read faster than bundle-20261016?

## Why

Patch 0061 turns GGML_CUDA_FA_PREFILL_NCOLS2=2 on by default on sm_75 (T2a; P154 speed, P156 quality). Every release
gets a post-zip check on the 2060 (control bytes, chosen settings, speed, one-token answers, min free).

## Plan and gate

Script header (gates declared before the run): "sha256 match; zip launcher 0 control bytes; --version commit
9fae15924e; FLASH_ATTN_EXT / GET_ROWS / SET_ROWS 0 FAIL; the default launch prints "window 262144 / q3_0" and "sparse
host-tail reads: auto"; a COLD 128k read (fresh server) TTFT <= 0.95 x P154's default (589.1 s) [P154 NCOLS2=2: 530.8
s]; a sweep 4k / 64k on a second server within 3 % of P150 (54.0 / 41.1); 0 one-token; trace min free >= 60 MiB."

## Method

Download the release asset (gh release download), sha256, Expand-Archive, the control-byte scan of the zip launcher, a
test copy with the BONSAI_BIN line, --version, op tests, then two servers with a 10 s VRAM trace each: cold128 (one
cold 128k prompt) and sweep (4k then 64k, an extending sequence: the 64k step evaluates 60,477 tokens).

## Verdict

536.77 s (bundle-20261016 589.1 s: 1.098x, = P154's NCOLS2=2 arm 530.8 s within 1.1 %); 4k 52.6 / 64k 40.6 tok/s; 0
one-token; min free 68 MiB.
