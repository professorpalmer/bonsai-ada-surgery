## Question

With replay on, a larger MTP draft no longer costs a recurrent plane per draft token. Which draft size (below the VRAM
line) and tail size (past it) decodes fastest on 8 GB?

## Why

Notebook 08:22 CDT: "With replay the launcher charges +7 MiB per extra draft token (FixedMiB -142 + 7 x (max(spec, deep)
- 1)), not a 144 MiB plane, so a larger draft on 8 GB is cheap for the first time." Without replay, draft 2 / 3 lost on
prose and at 60k (P35), and tail 2-4 lost at mid depth (P47).

## Plan and gate

Script header (declared before the run): "arms in one block: d11 = BONSAI_SPEC 1 / SPEC_DEEP 1 (the 8 GB default), d21 =
2 / 1, d22 = 2 / 2, d33 = 3 / 3. Per arm: det_answer 4k, 64k and 128k (each a cold read + 400 decoded tokens), the VRAM
line, min free, 0 CUDA errors / spill lines. Reported: decode tok/s per depth and arm (an arm wins at a depth if it beats
d11 by more than 3 %); greedy text may differ by rounding (drafting is not batch-invariant in attention), reported, not
gated."

## Deviations, incidents, void runs

- Found by this record writer: the #138 post says "the greedy text differs between draft sizes at every depth". Every
  larger draft differs from 1 / 1 at every depth, but 2 / 1 and 2 / 2 give the same text at 4k, and 2 / 1, 2 / 2 and
  3 / 3 the same at 64k. d11's 128k text equals P213 Bon's (same line 90,624), and d21 / d33's 128k text equals P213 A's
  (pinned 80,640): the same near ties fall both ways.
- One run per cell; 64k is within 1 % for 1 / 1, 2 / 1 and 2 / 2.

## Verdict

Reported. With replay, draft 2 / tail 2 is the best size on the 2060: +4.3 % at 4k, equal at 64k, +21.8 % at 128k, for
512 cells and no headroom loss. Draft 3 hurts below the line. The text changes with the draft size (rounding), so the
default needs a quality gate (P217).

## Corrections later

- P217: 2 / 2 passes the code-set quality gate (0 confident wrong, 0 changed items, like the rounding null).
- The 4070 (AD1 / AD2, AD3): fixed 2 / 2 is the best balance there too (code 128k +19.6 %); adaptive depth and 2 / 4 are
  not adopted; "only the large 128k gains of 2 / 2 ... stand out of the noise".
- P221 / P222: det_answer has only the code prompt. On quick_tps (code / prose / bash) in one block, 2 / 2 is -3.3 % at
  4k and -3.7 % at 64k against 1 / 1 without replay; prose and bash lose (acceptance 0.62 against 0.78). bundle-20261019c
  drafts 1 below the line and 2 past it (P222, option B).
