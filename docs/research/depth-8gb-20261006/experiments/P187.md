## Question

With 8 of the 16 full-attention layers on the unwindowed mask, does window 32k pass the R2 wrong-answer clause on the
2060? The clause (release plan, #138 21:58:42Z): "no **wrong** code where dense is right in more than 1 item overall".

## Why

The offline scoring of the earlier arms (E91): no tested arm passes, and dense layers are the only knob that moves the
count (window 32k: 2 + 4 wrong; 32k + even 4: prose 2). The cost model gives about 1.35x at 245k with 8 dense layers
(#138 23:45:51Z).

## Plan and gate

Script header (declared before the run): "bin-t5r3, window 32k / sink 1k / tail 1k +
dense=7:15:23:31:39:47:55:63 (8 of 16 full-attention layers), recipe as P182, the P170 code and prose sets. Reported:
ok, and WRONG answers on items dense gets right (code: 20 items; prose: the 9 right in both dense runs); the R2 clause
asks <= 1 overall. Cold times."

## Deviations, incidents, void runs

- Found by this record writer: the #138 post says "prose 21 is a miss". The answer names a wrong object ("leather"). It
  does not change the clause count (dense is wrong on 21 too).
- Found by this record writer: the result depends on the reference. Against P183 dense alone (the matched setting:
  bin-t5r3, `BONSAI_SPARSE=0`), P187 has 2 prose items wrong where dense is right: 22 and 23 ("The answer is **12**.").
  Against P170 alone it also has 2 (7 "bird", 22). Only the "right in both dense runs" reference (9 items) gives 1.
  Code has no matched (`BONSAI_SPARSE=0`) dense run on this card; its reference is P170 (automatic sparse decode, E94).
- n24 with this arm was not run on the 2060.

## Verdict

Reported. Window 32k with 8 dense layers reads the ~240k sets 1.28x faster than dense. Against the declared reference it
has 1 confident wrong answer where dense is right (prose 22), so it passes the clause on the 2060; against a single
dense run it has 2. On the 4070 the same arm fails the clause (3 wrong: code 17; prose 13, 18; 1.29x; E92).
