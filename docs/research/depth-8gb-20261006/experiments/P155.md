## Question

With SlotCache in the layer (save at the end of each prompt, restore the longest saved prefix), do restarts keep the
answers byte-identical and avoid the cold read, and do an edited history and short prompts behave as designed?

## Why

P153 showed that a saved slot restores a 245k conversation in seconds, but only if the next prompt extends the saved
tokens; with thinking on, a save after the reply does not help. T1-c saves at the end of the prompt (a prefill-only
call + save).

## Plan and gate

Script header (gates declared in the 06:45 design comment, copied before the run):

- Arms (temp 0): "M memory: one server + layer, cache OFF, turns 1-5 at 131,072 (think off), then the edited-history
  request (turn 3 --edit). R restart: before EVERY turn a fresh server + a fresh layer, cache ON (one folder, empty at
  the start), turns 1-5, then the edited request on a fresh server + layer. S short prompt: 4,000-token turn 1, layer
  cache off vs on, the same server. MT / RT thinking on (max_tokens 1024), 65,536, turns 1-3: memory vs restart +
  cache."
- "E1 R answers == M answers byte for byte at every turn; R turns 2-5: prompt_n <= new tokens of the turn + 512."
- "E3 the edited request: no restore for it (no saved file is a prefix of it; slot_events.txt shows no 'restored' in
  the Redit layer log), the whole prompt is read again (in the layer's prefill-only call: wall_s ~ a cold 128k read),
  and its answer == M's edited answer."
- "S the 4k answers byte-identical; no restore and no save at 4k."
- "Thinking on: RT turns 2-3 prompt_n <= new tokens + 512 (reported against MT; answers compared, not gated)."

## Method

(Planned.) p155_turn.py sends one turn through the layer: a facility document of --depth tokens (8 vault codes) + Q1;
each later turn appends the previous answer, a ~2.5k-token tool-output block and the next question. Answers of earlier
turns come from the arm's own state file, so two arms have the same history only if their answers agree.
