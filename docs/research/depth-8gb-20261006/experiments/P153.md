## Question

On the 8 GB card, can a long conversation be saved to disk after its first request, restored on a fresh server, and
continued with the same answer as the in-memory server, in seconds instead of a cold read?

## Why

Cold reads on 8 GB take 230 s at 64k, 611 s at 131k and 1,689 s at 245k (this run). The 4070's T1-b passed (restore +
continue at 245k in 2.2 s vs 468 s cold, byte-identical). The 2060 owns the server and launcher side.

## Plan and gate

Script header: "Per depth 65,536 / 131,072 / 245,000: server 1 request 1 (A) + save + request 2 (D2, in memory); server 2
fresh: restore + request 2 (B2). At 64k also server 3 fresh: request 2 with no restore (C2). Then the THINKING-ON case
at 64k (T1B_THINK=1, max_tokens 1024): the template drops the reasoning from the history, so request 2 may not extend
the saved tokens. Gates (declared before the run, as T1-b): G1 save / restore no error, server healthy. G2 B2 == D2
byte for byte. G3 prompt_n of request 2 after restore <= 1,024. G4 restore + request-2 prompt time <= 30 s at 245k.
Thinking-on arm: reported, not gated (expected: G3 fails if the reasoning is dropped from the history)."

## Method

t1b_slot.py: a facility document of the target depth with 8 vault codes. Request 1 lists the codes; the slot is saved
(POST /slots/0?action=save); request 2 asks one code. A fresh server restores the file (POST /slots/0?action=restore) and
sends request 2.

## Deviations, incidents, void runs

- The notebook names the middle depth "128k"; the run used 131,072 tokens.
- The thinking-on pair was run before the T1-c design was final (06:45 CDT: "P153 thinking pair decides the cheaper
  variant").

## Verdict

PASS (G1-G4). A 245k conversation continues 5.23 s after a restart (cold: 1,688.9 s for request 1).
With thinking on, the saved slot holds the reasoning tokens that the template drops from the next prompt, so the
restore does not help (234.36 s).

## What it changed

- The T1-c design (06:45 CDT, #138) saves at the END OF THE PROMPT (a prefill-only call + save), so the next turn always
  extends the saved tokens, also with thinking on. P155 tests it in the layer.

## Toolbox (for the next model)

- Continuation rule: a saved slot only helps if the next prompt starts with exactly the saved tokens. Save at the end
  of the prompt (before the reply), not after the reply: chat templates can drop or change the reply (here the
  reasoning) in the next turn's history.
- Data (8 GB, q3_0, NVMe): slot files 1,049 MiB at 65,690 cells, 1,938 MiB at 130,567 cells, 3,492 MiB at 244,087 cells; save
  1.65-7.55 s, restore 1.12-3.41 s.
