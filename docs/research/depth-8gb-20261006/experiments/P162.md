## Question

Can a client send a long document once with `"prefill_only": true`, so that the layer reads and saves it, and then ask
a question after a server restart in a few seconds, with the same answer as a cold read?

## Why

P160 showed the saved-conversation path on the 2060, but the first turn still paid the cold read while the user waited.
T1-d moves that cost to a time the user chooses: the client "reads ahead", and the first real question restores the
saved state.

## Plan and gate

Script header (gates declared before the run):

- "1. server + layer: read ahead [user: a ~131k document] ("prefill_only": true). 2. fresh server + fresh layer (a
  restart): ask [user: document], [user: question] -> the layer restores. 3. control: fresh server + layer with the
  cache OFF: the same ask, cold."
- "Gates (declared before the run): 1 returns prefill_only with slot_cache_saved ~= the document's tokens; 2 restores,
  its wall <= 15 s, its answer == the control's answer; 0 CUDA errors in all server logs."

Notebook rule in the plan entry: "the question must be a NEW message" (so that the question extends the saved state).

## Method

p162_drive.py builds the t1b_slot document at depth 131,072 and sends it through the layer on :8081, streamed,
`max_tokens` 64, temperature 0, thinking off, `code_interpreter` false. Phase readahead sends `[user: document]` with
`"prefill_only": true`. Phase ask sends `[user: document], [user: Q1]` (Q1: "List the access codes of vaults 1 to 8, one
per line, as 'vault N: CODE'. Then stop."). Each step starts a fresh server and a fresh layer.

## Deviations, incidents, void runs

- `max_tokens` 64 cut both answers after "vault 7:". So the answer compare covers vaults 1-6 only. The #138 post says
  so ("max_tokens 64 cut both at the same place").
- The layer copy is PR #159 at 5e90852, before the review fixes (E69). The fixed layer (main bad2d9a) ran on the 2060
  later, in P164 and P165 (serve-1017).
- The `.draft` sidecar has the cache file's name (`lc-<sha>.bin.draft`). So the PR #157 fix for review item B1 (the
  sidecar was not renamed, P160) works with read ahead. The #138 post says "the B1 rename works".
- The notebook entry "22:45 CDT P162 result" comes after the entry "22:55 CDT (clock time ...)" in the notebook. The
  #138 post is at 03:42:44Z (22:42 CDT).

## Verdict

PASS. Read ahead works on the 8 GB card with MTP and the shared pool on: a 130,452-token document read once (563.8 s),
then after a full restart a new question answers in 6.25 s (restore 1.84 s + 39 tokens), with the cold control's
answer (560.7 s). The draft sidecar is saved and restored with the read-ahead state.
