## Question

Does the fixed-grid chunk skip change any bit of the answer, when the rig's numeric state is the same for both arms?

## Why

P175 S-1 compared the skip with P174b, which ran in the other numeric state of the rig (events E82). A test of
exactness needs both arms in one block, and a third arm to catch a drift inside the block.

## Plan and gate

Script header: "bin-t5s, window 16k / sink 1k / tail 1k, det_answer at 128k, back to back in one block: A =
GGML_CUDA_FA_CHUNK_SKIP=0 (mask only), B = skip on (default), C = skip off again (a drift check). Gate: A = B = C sha256
(if A = C but B differs, the skip is not exact). Also the cold times (A / C mask only vs B skip)."

## Verdict

EXACT. With the 16k window at 128k, the fixed-grid chunk skip gives the same answer bytes as the mask-only read (off /
on / off in one block). It cuts the 128k prompt eval from 532.5 s to 483.1 s (1.10x, as P175 S-3). The mask-only read
at 128k has the dense speed (532.5 s vs P168's ~532.4 s).
