## Deviations, incidents, void runs

- Found by this record writer: dprose does not use the P170 setting. P170 (and P188 later) ran the zip bins with
  automatic sparse (the launcher default). Their server logs show "sparse auto: band 224-240k: dense 222.6 ms, sparse
  166.9 ms per graph -> sparse": the answer tokens at ~241k came from sparse host-tail reads ("keeps 615 of 2464 pages +
  recent"). dprose ran bin-t5r3 (window unset) with `BONSAI_SPARSE=0`. No det_answer ran in P183. So the 4 flips can come
  from the decode setting, from the bins, or from the numeric state; the run does not separate them. The notebook and
  #138 (02:28:09Z, 03:22:54Z) call P183 "the other drift state"; that is not measured (E94).
- Found by this record writer: wprose repeats P178 R-4 exactly. P178 ran in state A (its R-0 hashes). This is weak
  evidence that P183 also ran in state A (not tested).
- dprose is the only dense run with the T5 settings (bin-t5r3, `BONSAI_SPARSE=0`), so it is the matched dense
  reference for the T5 arms on the prose set.

## Toolbox (for the next model)

- Data (8 GB, 2060): T5 window 32k at 128k: cold 414.3 s (1.29x), n24 23/24; at ~241k prose 808.9 s (1.76x).
- Method: repeat both the reference and the test arm before a verdict; a lossy arm that repeats exactly while the
  reference moves points at a difference in the reference's setting.
- Pitfall: a "dense again" arm must use the reference's bins and every setting (here `BONSAI_SPARSE`).
